# Сеть двух офисов на Eltex ESR и Альт Linux — порядок команд

**Как читать:**
- **▶ N.M** — каркас. Копируй блоки подряд, ничего не пропуская.
- **⚠** — важное, не пропускать.
- **Машина:** — на какой машине вводишь блок.
- **Где взять:** — перед блоком: откуда взять значения, которые в нём впервые встречаются. Сразу впиши в блокнот.
- **Посчитай:** — вычислить адрес или маску.
- `«текст в ёлочках»` — вставь значение из блокнота, ёлочки не копируй.
- Серые блоки (цитаты) — «Проверка» и «Если ошибка». Всё работает — листай мимо.
- «У работодателя» — данные, которые дают в условии: таблицы, схема, текст задания.
- Клиент-2 — только если он есть на схеме. Нет — пропускай всё, где он упомянут.

**Правила:**
- ⚠ ESR: каждый блок заканчивается `end` → `commit` → `confirm`. `commit` внутри `(config)#` не работает. Без `confirm` через 10 минут всё откатится.
- ⚠ Профили NetworkManager удаляем строкой с `grep -E`: она удаляет профили, активные на твоих портах, и все неактивные проводные профили (у них в DEVICE `--`). Профили, активные на чужих портах, не трогает.
- ⚠ apt через роутер ESR может быть очень медленным (десятки минут). Пакеты ставь **сразу**, как у машины появился интернет (5.4), и параллельно делай шаг 6.

## Как считать адреса

- «Сеть» — адрес до `/` у работодателя. +1, +2, +3 прибавляем к последнему числу: 10.1.1.0 +2 = 10.1.1.2.
- Сети офисов: шлюз (роутер) = сеть +1, сервер / клиент / коммутатор = +2, клиент-2 = +3.
- Внешние сети: провайдер = +1, роутер = +2. Туннель: роутер-1 = +1, роутер-2 = +2.
- Маска по «не более N адресов»: 4→30 · 8→29 · 16→28 · 32→27 · 64→26 · 128→25 · 256→24 · 512→23. «Минимально возможная» (туннель) = 30.

## Шаг 0 · Схема → блокнот (до любых команд, ~5 минут)

### ▶ 0.1 Найди роли на схеме

| Роль в статье | Как узнать на схеме |
|---|---|
| Провайдер | Linux, подключён к облаку «Интернет» и к обоим роутерам |
| Роутер-1 | ESR, за которым стоит коммутатор (офис с VLAN) |
| Роутер-2 | ESR, за которым сразу сервер |
| Коммутатор | Linux-коммутатор в офисе роутера-1 |
| Сервер-1, Клиент-1 | за коммутатором: сервер и клиент |
| Сервер-2 | за роутером-2 |
| Клиент-2 | **только если нарисован** за роутером-2. Нет его — пропускай все строки и блоки с ним |

### ▶ 0.2 Перепиши порты и сети в блокнот
- Подпись у конца линии рядом с устройством — это **порт этого устройства** (ens19, gi1/0/2…). Для ESR пиши в блокнот без `gi`: `1/0/2`.
- Облако на линии — это **сеть между устройствами**, а не устройство:
  - облако «провайдер ↔ роутер-1» = внешняя сеть-1, «провайдер ↔ роутер-2» = внешняя сеть-2;
  - облако «роутер-1 ↔ коммутатор» = транк. Своих адресов у него нет, через него идут все три VLAN;
  - облако у сервера-1 = VLAN серверов, у клиента-1 = VLAN клиентов, у сервера-2 = сеть офиса-2;
  - VLAN управления облаком обычно не рисуют: он внутри транка, адрес в нём получает коммутатор.

### ▶ 0.3 Сверь провода со схемой
**Машина:** каждая Linux-машина:
```
ip -br link
```
- Порт, которого нет на схеме (обычно первый, ens18), — служебный. **Не трогай его.**
- Proxmox: ВМ → Hardware. У каждого `netN` указаны MAC и мост: net0 = ens18, net1 = ens19, net2 = ens20, net3 = ens21. MAC из `ip -br link` совпал с MAC в `netN` → этот порт сидит в этом мосту. Мост должен соответствовать облаку со схемы.

**Машина:** каждый ESR:
```
show interfaces status
```
Сверь MAC портов с гипервизором так же.

> **Только если стенд не собран** (у ВМ нет нужных сетевых карт, или все карты в одном мосту) — Proxmox:
> 1. Узел → System → Network → Create → Linux Bridge. По одному мосту на каждое облако схемы, кроме «Интернет» (он уже есть, обычно vmbr0). IP и Ports не заполняй → Apply Configuration.
> 2. ВМ → Hardware → Add → Network Device → нужный Bridge, Model VirtIO, галку Firewall сними.
> 3. Карты добавляй в порядке портов на схеме: следующая после net0 станет ens19, потом ens20 и т.д. На ESR после добавления сверь MAC через `show interfaces status`.
> 4. В другом гипервизоре — то же самое: одно облако = одна отдельная внутренняя сеть (мост).

## Шаг 1 · Провайдер (Linux)

**Где взять:** «пароль root» — у работодателя (данные стенда). Входи root / «пароль root».
**Где взять:** «имя провайдера» — в таблице DNS-имён провайдера обычно нет (там строки про его порты — это доп. имена, шаг 8). Бери со схемы, маленькими: ISP → isp. «домен» — в таблице DNS-имён: всё после первой точки.
**Где взять:** «часовой пояс» — город у работодателя → `timedatectl list-timezones | grep -i mosc` (первые буквы города латиницей, по-английски: Moscow, Samara, Yekaterinburg…). Пишешь целиком, например `Europe/Moscow`.

### ▶ 1.1 Имя, пояс
```
hostnamectl set-hostname «имя провайдера».«домен»; exec bash
#-----------------------------------------
timedatectl set-timezone «часовой пояс»
#-----------------------------------------
date +%z
```
**Где взять:** «сдвиг UTC» — из `date +%z`: +0300 → +3.

**Где взять:** «порт провайдера к интернету», «… к роутеру-1», «… к роутеру-2» — схема; на машине `ip -br a` (вида ens19).
**Где взять:** «внешняя сеть-1», «маска внешней сети-1» — у работодателя: сеть провайдер–роутер-1, до `/` и после. То же для сети-2.
**Посчитай:** «IP провайдера к роутеру-1» = «внешняя сеть-1» +1. «внешний IP роутера-1» = +2. То же для сети-2.

> **До 1.2:** `nmcli con show` — смотри колонку DEVICE. Удалятся профили на портах к роутерам и неактивные проводные (DEVICE `--`). Профиль на порту к интернету активен — его команда не тронет.

### ▶ 1.2 Адреса
```
nmcli -g UUID,TYPE,DEVICE con show | grep -E ':802-3-ethernet:$|:(«порт провайдера к роутеру-1»|«порт провайдера к роутеру-2»)$' | cut -d: -f1 | xargs -r -n1 nmcli con del
#-----------------------------------------
nmcli con add con-name toR1 ifname «порт провайдера к роутеру-1» type ethernet ip4 «IP провайдера к роутеру-1»/«маска внешней сети-1»
#-----------------------------------------
nmcli con add con-name toR2 ifname «порт провайдера к роутеру-2» type ethernet ip4 «IP провайдера к роутеру-2»/«маска внешней сети-2»
```

### ▶ 1.3 Forward + NAT
```
sed -i 's/ip_forward = 0/ip_forward = 1/' /etc/net/sysctl.conf
#-----------------------------------------
sysctl -w net.ipv4.ip_forward=1
#-----------------------------------------
iptables -t nat -A POSTROUTING -o «порт провайдера к интернету» -j MASQUERADE
#-----------------------------------------
iptables-save > /etc/sysconfig/iptables
#-----------------------------------------
systemctl enable --now iptables
```

> **Проверка:** `ip -br a` → на порту к интернету адрес по DHCP, на портах к роутерам — твои адреса · `ping -c2 8.8.8.8` · `sysctl net.ipv4.ip_forward` = 1 · `iptables -t nat -S` → MASQUERADE
>
> **Если ошибка:**
> - на порту к интернету нет адреса → `nmcli con add con-name inet ifname «порт провайдера к интернету» type ethernet` (это DHCP), потом `nmcli con up inet`
> - `grep ip_forward /etc/net/sysctl.conf` ничего не выводит → `echo 'net.ipv4.ip_forward = 1' >> /etc/net/sysctl.conf`
> - iptables / служба not found → `apt-get install -y iptables`, повтори 1.3
> - на порту снова «Проводное подключение» → повтори первую строку 1.2

## Шаг 2 · Роутер-1 (ESR)

**Где взять:** «новый пароль admin» — данные стенда; не дали — придумай.

### ▶ 2.0 Вход и смена заводского пароля
Вход: логин `admin`, пароль `password`. Появится `(change-expired-password)#` — роутер не примет ничего, пока не сменишь пароль:
```
password «новый пароль admin»
commit
confirm
```

> **Если ошибка:**
> - `password` не подходит при входе → пароль уже сменён: входи `admin` / «новый пароль admin»
> - `Syntax error` на голый пароль → перед паролем нужно слово `password`
> - `reboot` в этом режиме не работает — это нормально, он не нужен
**Где взять:** «имя роутера-1» — таблица DNS-имён, до первой точки.
**Где взять:** «порт роутера-1 к провайдеру», «порт роутера-1 к коммутатору» — схема, вида 1/0/2.
**Где взять:** «VLAN серверов», «VLAN клиентов», «VLAN управления» — у работодателя (номера).
**Где взять:** «сеть серверов», «сеть клиентов», «сеть управления» и N каждой — у работодателя: адрес до `/` и «не более N адресов».
**Посчитай:** «маска …» — по N. «шлюз …» = своя сеть +1. Сразу посчитай и «IP сервера-1», «IP клиента-1», «IP коммутатора» = своя сеть +2.

### ▶ 2.1 Имя + интерфейсы
```
configure
hostname «имя роутера-1».«домен»
interface gigabitethernet «порт роутера-1 к провайдеру»
 ip firewall disable
 ip address «внешний IP роутера-1»/«маска внешней сети-1»
exit
interface gigabitethernet «порт роутера-1 к коммутатору»
 ip firewall disable
exit
interface gigabitethernet «порт роутера-1 к коммутатору».«VLAN серверов»
 ip firewall disable
 ip address «шлюз серверов»/«маска серверов»
exit
interface gigabitethernet «порт роутера-1 к коммутатору».«VLAN клиентов»
 ip firewall disable
 ip address «шлюз клиентов»/«маска клиентов»
exit
interface gigabitethernet «порт роутера-1 к коммутатору».«VLAN управления»
 ip firewall disable
 ip address «шлюз управления»/«маска управления»
exit
end
commit
confirm
```

### ▶ 2.2 Маршрут + NAT
```
configure
ip route 0.0.0.0/0 «IP провайдера к роутеру-1»
nat source
 ruleset INET
  to interface gigabitethernet «порт роутера-1 к провайдеру»
  rule 10
   action source-nat interface
   enable
  exit
 exit
exit
end
commit
confirm
```

**Где взять:** «логин роутеров», «пароль роутеров» — у работодателя (учётка для роутеров).

### ▶ 2.3 Пользователь + пояс
```
configure
username «логин роутеров»
 password «пароль роутеров»
 privilege 15
exit
clock timezone gmt «сдвиг UTC»
end
commit
confirm
```

> **Проверка:** `show ip interfaces` → 4 адреса, Up · `ping «IP провайдера к роутеру-1»`, `ping 8.8.8.8` → `!!!!!` · `show date` → твой GMT-сдвиг
>
> **Если ошибка:**
> - провайдер не пингуется → перепутаны порты: `show interfaces status`, сверь MAC со схемой; поменяй порты местами в 2.1 и 2.2
> - hostname с точкой не принимается → `hostname «имя роутера-1»` + `domain name «домен»`
> - ругается на bridge / security-zone / dhcp на порту → внутри interface: `no bridge-group`, `no security-zone`, `no ip address dhcp`, потом `ip firewall disable`
> - в `show date` совсем неверное время → `clock set ?` в режиме `#` (не проверено; обычно нужен только пояс)
> - `ping … count 3` = Illegal → просто `ping X`

## Шаг 4 · Коммутатор (Linux)

**Где взять:** «имя коммутатора» — таблица DNS-имён или схема, маленькими.
**Где взять:** «порт коммутатора к роутеру-1», «… к серверу-1», «… к клиенту-1» — схема; на машине `ip -br a`.
**Где взять:** «внешний DNS» — у работодателя.

### ▶ 4.1 Имя, пояс
```
hostnamectl set-hostname «имя коммутатора».«домен»; exec bash
#-----------------------------------------
timedatectl set-timezone «часовой пояс»
```

> **До 4.2:** `nmcli con show` — удалятся профили на трёх портах коммутатора и неактивные проводные (DEVICE `--`).

### ▶ 4.2 Мост с VLAN
```
nmcli -g UUID,TYPE,DEVICE con show | grep -E ':802-3-ethernet:$|:(«порт коммутатора к роутеру-1»|«порт коммутатора к серверу-1»|«порт коммутатора к клиенту-1»)$' | cut -d: -f1 | xargs -r -n1 nmcli con del
#-----------------------------------------
nmcli con add type bridge con-name br0 ifname br0 bridge.stp no bridge.vlan-filtering yes bridge.vlans «VLAN управления» ipv4.method disabled ipv6.method disabled
#-----------------------------------------
nmcli con add type bridge-slave con-name up ifname «порт коммутатора к роутеру-1» master br0 bridge-port.vlans "«VLAN серверов»,«VLAN клиентов»,«VLAN управления»"
#-----------------------------------------
nmcli con add type bridge-slave con-name srv ifname «порт коммутатора к серверу-1» master br0 bridge-port.vlans "«VLAN серверов» pvid untagged"
#-----------------------------------------
nmcli con add type bridge-slave con-name cli ifname «порт коммутатора к клиенту-1» master br0 bridge-port.vlans "«VLAN клиентов» pvid untagged"
#-----------------------------------------
nmcli con add type vlan con-name mgmt ifname mgmt dev br0 id «VLAN управления» ip4 «IP коммутатора»/«маска управления» gw4 «шлюз управления» ipv4.dns «внешний DNS»
#-----------------------------------------
systemctl restart NetworkManager
#-----------------------------------------
nmcli con up mgmt
```

> **Проверка:** `bridge vlan show` → порт к роутеру: три VLAN; к серверу: VLAN серверов `PVID Egress Untagged`; к клиенту: VLAN клиентов; br0: VLAN управления (лишний VLAN 1 — норма) · `ping -c2 «шлюз управления»` · `ping -c2 8.8.8.8`
>
> **Если ошибка:**
> - у mgmt нет адреса → `nmcli con up br0`, потом `nmcli con up mgmt`

## Шаг 9 · Сервер-1 — RAID

```
(`$i` не заменяй — это номер пользователя.)

> **Проверка:** `systemctl is-active samba` → active · `samba-tool group listmembers «группа офиса-1»` → все юзеры офиса-1 · то же для офиса-2
>
> **Если ошибка:**
> - `Couldn't find package task-samba-dc` → повтори `apt-get update`
> - provision упал → снова первые три строки 11.1, потом provision

### ▶ 11.3 Клиент-1 — вход в домен
```
host -t SRV _ldap._tcp.«домен»
#-----------------------------------------
system-auth write ad «домен» «имя клиента-1» «КОРОТКОЕ ИМЯ ДОМЕНА» Administrator '«пароль домена»'
```
`Joined …` и следом `DNS update failed!` — это норма.

**Где взять:** «команды для sudo» — у работодателя (что разрешить группе офиса-1).
**Где взять:** «пути команд sudo» — вывод `which «команды для sudo»`, через запятую с пробелом: `/usr/bin/nano, /bin/cat`.

> **До 11.4:** `which «команды для sudo»` → по пути на каждую. nano пусто → `apt-get install -y nano`.

### ▶ 11.4 Клиент-1 — вход только группе офиса-1 + sudo
```
sed -i 's/^access_provider = ad/access_provider = simple\nsimple_allow_groups = «группа офиса-1»/' /etc/sssd/sssd.conf
#-----------------------------------------
grep -A1 access_provider /etc/sssd/sssd.conf
#-----------------------------------------
control sudo public
#-----------------------------------------
echo '%«группа офиса-1» ALL=(ALL) «пути команд sudo»' >> /etc/sudoers
#-----------------------------------------
visudo -c
#-----------------------------------------
reboot
```

> **Проверка:** grep → `access_provider = simple` + `simple_allow_groups = …` · после ребута: `id «юзер офиса-1 без цифры»1` → группа офиса-1 · вход этим юзером («пароль домена») пускает, `sudo id` → uid=0, `sudo -l` → только твои команды · вход юзером офиса-2 → отказ
>
> **Если ошибка:**
> - id: no such user → `host -t SRV _ldap._tcp.«домен»`, `systemctl restart sssd`, подожди минуту
> - Clock skew too great → время на клиенте-1 и сервере-2 должно совпадать (`date` на обеих)
> - grep не показал simple → в sssd.conf нет строки `access_provider = ad`: допиши обе строки руками в секцию `[domain/…]`
> - `visudo -c`: в имени группы есть пробел или @ → возьми имя в кавычки: `%"группа" ALL=(ALL) …`
>
> Клиент-2, если есть (не проверено): как 11.3 с «имя клиента-2»; в 11.4 `simple_allow_groups = «группа офиса-2»`, строку sudoers не добавлять. NFS — как 10.2.
